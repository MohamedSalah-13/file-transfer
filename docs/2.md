## المتطلبات بعد التوضيح

- **كل عميل يرى ملفاته فقط** (خصوصية/عزل).
- **إرسال مباشر لعميل محدد** (Client A يرسل إلى Client B عبر السيرفر).
- واجهة **Server JavaFX** تعرض التحميلات (Uploads/Downloads/Transfers) مع **Progress**.
- واجهة **Client JavaFX**:
    - تعرض “ملفاتي” (التي وصلتني/أرسلتها)
    - قائمة المستخدمين المتصلين
    - عند اختيار مستخدم + ملف ⇒ إرسال
    - عند الضغط على ملف وارد ⇒ تنزيل/حفظ
    - **Progress** أثناء الإرسال/التحميل

سأقترح لك تصميم “واقعي وبسيط” مثل واتساب: **السيرفر وسيط** (Relay) ويقرر لمن يذهب الملف، ويضمن أن كل مستخدم لا يرى إلا ملفاته.

---

## 1) تصميم عام (Architecture)

### A) تعريف “هوية المستخدم”
لازم كل عميل يعرّف نفسه للسيرفر عند الاتصال:
- إما `username + password` (بسيط)
- أو `username` فقط (للتجربة)

سأفترض الآن **username فقط** لتسريع التنفيذ، ويمكن إضافة كلمة مرور لاحقًا.

### B) السيرفر كوسيط نقل
عند إرسال ملف من A إلى B:
1. A يتصل بالسيرفر ويقول: `SEND_FILE to=B fileName size`
2. السيرفر يتأكد أن B “مسجل/متصل” (أو يحفظ الملف له إن كان Offline)
3. السيرفر:
    - **إما** يخزّن الملف في مجلد B ثم يرسل إشعارًا لـ B
    - **أو** يعمل Relay مباشر إلى Socket الخاص بـ B (أقرب لواتساب)

الأبسط والأكثر ثباتًا:  
✅ **يخزن على السيرفر في Inbox الخاص بـ B** ثم يرسل إشعار “وصلتك رسالة”.

> هذا يضمن أن B يقدر ينزل الملف حتى لو كان الاتصال ضعيف/انقطع لحظة.

---

## 2) عزل الملفات: “كل عميل يرى ملفاته فقط”

على السيرفر أن يكون عنده مجلد لكل مستخدم:
- `server-storage/<username>/inbox/` (ملفات وصلت)
- `server-storage/<username>/sent/` (اختياري للأرشفة)

وعند تنفيذ `LIST_MY_FILES`:
- السيرفر يقرأ فقط من مجلد `<username>/inbox` (أو كلاهما حسب تصميمك)
- يرجع القائمة لهذا المستخدم فقط.

---

## 3) بروتوكول أوامر (مقترح عملي)

استخدم `DataInputStream/DataOutputStream` و`writeUTF` + `writeLong`.

### أوامر أساسية
1) **HELLO**
- Client → Server:
    - `"HELLO"`, `username`
- Server → Client:
    - `"HELLO_OK"` أو `"HELLO_TAKEN"`

2) **LIST_USERS (المتصلين)**
- Client → Server: `"LIST_USERS"`
- Server → Client:
    - `"USERS"`, `count`, ثم usernames

3) **SEND_FILE (إرسال إلى مستخدم محدد)**
- Client → Server:
    - `"SEND_FILE"`, `toUser`, `fileName`, `fileSize`
    - ثم bytes الملف
- Server:
    - يحفظ الملف داخل `server-storage/toUser/inbox/<uniqueId>__fileName`
    - يرد على المرسل: `"SEND_OK"`
    - ويرسل للمستلم (لو عنده قناة إشعارات مفتوحة) إشعار: `"INCOMING_FILE", fromUser, fileId, fileName, fileSize`

4) **LIST_MY_FILES**
- Client → Server: `"LIST_MY_FILES"`
- Server → Client:
    - `"MY_FILES"`, `count`, ثم لكل ملف: `fileId`, `fileName`, `fileSize`, `fromUser`, `timestamp`

5) **DOWNLOAD**
- Client → Server:
    - `"DOWNLOAD"`, `fileId`
- Server → Client:
    - `"FILE"`, `fileName`, `fileSize`
    - ثم bytes

> `fileId` مهم عشان تضمن عدم التعارض بين أسماء الملفات ولتتبع من أرسل ماذا.

## 4) كيف نعرض Progress على السيرفر والعميل (نفس الفكرة)

### العميل
- عند الإرسال: `UploadTask` يقرأ الملف chunk chunk ويحدّث `updateProgress(sent, size)`
- عند التنزيل: `DownloadTask` يقرأ من الشبكة chunk chunk ويحدّث `updateProgress(received, size)`
- واجهة JavaFX تربط `progressProperty()` مع `ProgressBar`.

### السيرفر (واجهة “شاشة التحميلات”)
كل عملية نقل تعتبر **TransferSession**:
- `id`
- `fromUser`
- `toUser`
- `fileName`
- `direction` (UPLOAD_TO_SERVER / DOWNLOAD_TO_CLIENT)
- `bytesDone`
- `totalBytes`
- `progressProperty`

وعند استقبال bytes من A أو إرسال bytes إلى B:
- تحدّث كائن الـ Session
- وتعمل `Platform.runLater` لتحديث الـ TableView (أو تستخدم ObservableList + Properties)

---

## 5) “مهم جدًا”: قناة إشعارات للمستلم (Realtime)

في واتساب، المستلم يعرف فورًا أن فيه ملف جديد. لتعملها ببساطة:

### خيار 1 (مستحسن وبسيط)
كل عميل يفتح **اتصال دائم** للسيرفر (Socket واحد)، والسيرفر يرسل عليه:
- إشعارات `INCOMING_FILE`
- ردود أوامر `LIST_USERS`, `MY_FILES`, ...

يعني: نفس الـ Socket عليه “أوامر + إشعارات” (لازم تفصل بين أنواع الرسائل بالبروتوكول).

### خيار 2
Socket للأوامر + Socket منفصل للإشعارات  
(أكثر تعقيدًا بدون فائدة كبيرة للمشروع).

✅ أنصح بخيار 1: Socket دائم واحد لكل عميل.

## 6) شكل شاشات JavaFX (اقتراح عملي)

### Server UI
**TableView<TransferSession>**
- From | To | File | Size | ProgressBar | Status | Speed (اختياري)

**ملاحظة**: “Speed” سهلة: كل 1 ثانية احسب (bytesDelta / 1s)

### Client UI
- يسار: قائمة المستخدمين المتصلين (ListView)
- وسط: قائمة “Inbox (الملفات الواردة)” (TableView)
- أعلى: زر “Choose File” + زر “Send”
- أسفل: قائمة Transfers الحالية (Progress لكل عملية)

## 7) أسئلة صغيرة قبل ما أكتب لك الهيكل النهائي (لتجنب إعادة العمل)

1) هل تريد دعم **Offline**؟  
   يعني لو B غير متصل، السيرفر يحفظ الملف ويظهر له لاحقًا عند الاتصال؟
    - أنا أميل لـ **نعم** (وسهل جدًا مع فكرة inbox).

2) هل تريد حد أقصى لحجم الملف (مثلاً 200MB)؟  
   هذا يؤثر على البافر/التعامل مع الذاكرة، لكن عمومًا سنبث Streaming بدون تحميل كامل بالذاكرة.

إذا قلت “نعم للأوفلاين” وذكرت حد الحجم (أو “بدون حد الآن”) سأعطيك مباشرة:
- هيكل Packages مقترح للمشروع (server/client/shared)
- تعريف `Message`/`Command` ثابت
- كود مسارات: `HELLO`, `LIST_USERS`, `SEND_FILE`, `LIST_MY_FILES`, `DOWNLOAD`
- وربط JavaFX TableView مع ProgressBar للـ Server والـ Client بطريقة نظيفة.
